# MVP 开发任务清单

> 状态：v1.0 AI 开发任务基线  
> 规则：按依赖顺序执行；不得以临时 LLM 文本代替未完成的确定性系统。

## 1. 优先级

- `P0`：MVP 必须，阻塞端到端流程。
- `P1`：MVP 发布必须，但不一定阻塞最早原型。
- `P2`：可在基础稳定后完成。

每项任务完成必须同时满足：代码、测试、简短文档、无未解释的 TODO、相关验收命令通过。

## 2. 里程碑

```text
M0 仓库骨架
 -> M1 无 LLM 生命历程原型
 -> M2 存档与重放
 -> M3 Lore Pack 与 Coverage Gate
 -> M4 受控 LLM 叙事
 -> M5 完整首个人生内容
 -> M6 发布候选
```

## 3. Epic A：仓库与基础设施

### A-01（P0）初始化 Python 项目

产物：`pyproject.toml`、`src/`布局、测试目录、Ruff/MyPy/pytest 配置、CLI 入口。  
依赖：无。  
验收：

- `python -m noosphere40k version`输出版本。
- `pytest`、`ruff check .`和核心包 MyPy 通过。
- `.env`、存档、私有资料目录进入 `.gitignore`。

### A-02（P0）领域枚举与错误类型

实现文档规定的 CampaignStatus、LifeStage、事实类型、稳定错误码。  
依赖：A-01。  
验收：序列化值契约测试通过，未知枚举严格拒绝。

### A-03（P0）配置与密钥

实现默认配置、用户配置、环境变量和 CLI 覆盖。  
依赖：A-01。  
验收：`doctor`不泄露密钥；无 key 时可使用 Stub Provider。

### A-04（P1）结构化日志与 trace ID

依赖：A-01。  
验收：单回合日志可按 trace ID 聚合，不含 API key 和私有资料正文。

## 4. Epic B：规则与生命历程

### B-01（P0）属性、技能与修正模型

依赖：A-02。  
验收：范围校验、未知技能、重复修正和无来源修正均有测试。

### B-02（P0）随机数服务与 RandomDrawn 事件

依赖：B-01、C-01。  
验收：可注入固定骰点；生产代码不存在第二个随机入口。

### B-03（P0）d100 通用检定

依赖：B-01、B-02。  
验收：目标值钳制、01/100、难度档、成功幅度、公开/暗骰测试通过。

### B-04（P0）年龄与阶段转换

依赖：B-01、C-02。  
验收：阶段不可由 LLM 直接修改；时间跳跃可预览、确认、结算和重放。

### B-05（P1）成长与职业系统

依赖：B-04。  
验收：技能来自经历事件；职业路线检查年龄、前置技能、关系和内容包。

### B-06（P1）伤势、压力、腐化与健康

依赖：B-03。  
验收：所有终局条件可解释到事件链；儿童默认内容限制生效。

### B-07（P1）简化战斗

依赖：B-03、B-06。  
验收：行动经济、命中、伤害、护甲、撤退和死亡使用确定性规则；LLM 无权改数值。

### B-08（P1）死亡、遗产与一生纪事数据

依赖：B-04、B-05、B-06、C-03。  
验收：任意阶段死亡均进入 TERMINAL，并可从事件生成一致年表。

## 5. Epic C：事件、数据库与存档

### C-01（P0）EventEnvelope 与 reducer

依赖：A-02。  
验收：事件 reducer 为纯函数；未知事件拒绝；状态哈希稳定。

### C-02（P0）SQLite Schema 与迁移器

依赖：C-01。  
验收：空库自动迁移；重复迁移幂等；失败保留原库。

### C-03（P0）Campaign Repository

依赖：C-02。  
验收：乐观版本冲突测试；事件序列无空洞和重复。

### C-04（P0）快照与事件重放

依赖：C-03。  
验收：从零重放与快照加载产生相同状态哈希。

### C-05（P0）自动保存、备份与恢复

依赖：C-03、C-04。  
验收：模拟提交中断后最近已提交回合可加载；损坏库只读打开。

### C-06（P1）导入与导出

依赖：C-05。  
验收：ZIP 防路径穿越；不包含密钥、私有原文或私有向量。

### C-07（P1）内容包版本锁

依赖：C-03、D-02。  
验收：哈希不符时禁止写入，只读模式仍可查看与导出。

## 6. Epic D：Lore 与内容包

### D-01（P0）Lore Pydantic Schema

依赖：A-02。  
验收：Source、Fact、Entity、Glossary、Knowledge 模型契约测试通过。

### D-02（P0）Pack Loader 与 manifest 依赖解析

依赖：D-01。  
验收：缺依赖、版本冲突、重复 ID、非法路径和未知 Schema 被拒绝。

### D-03（P0）Lore SQLite Repository 与 FTS5

依赖：C-02、D-01。  
验收：运行查询永远不返回未批准事实；中英文别名可检索。

### D-04（P0）Lore Coverage Gate

依赖：D-03。  
验收：实现七类裁决结果；hard requirement 缺失时不能调用 Narrator。

### D-05（P0）角色知识过滤

依赖：D-03、C-03。  
验收：百科解锁不改变角色知识；角色观点与客观事实分离。

### D-06（P0）Claim Guard

依赖：D-04、E-03。  
验收：无 fact ID 正史断言、越界原创和年代冲突均阻止提交。

### D-07（P1）来源导入与净化框架

依赖：D-01、D-02。  
验收：导入器不执行文档指令；提示注入和压缩炸弹夹具通过。

### D-08（P1）人工审核工作流

依赖：D-07。  
验收：candidate 不能直接变 approved；批准操作记录审核者和时间。

### D-09（P1）Galaxy Primer 基础包骨架

依赖：D-02、D-08。  
验收：12 个主题域、覆盖报告和空缺列表可生成；不得用占位内容冒充批准事实。

### D-10（P1）Campaign Canon Pack 骨架

依赖：D-02、D-08、F-01。  
验收：每个剧情节点 hard requirement 满足率可计算。

## 7. Epic E：LLM 管线

### E-01（P0）LLMProvider 与 Stub Provider

依赖：A-03。  
验收：Stub 在离线环境返回固定结构化响应；超时和取消有稳定错误。

### E-02（P0）OpenAI-compatible Provider

依赖：E-01。  
验收：base URL、model、key 可配置；厂商错误映射稳定；日志脱敏。

### E-03（P0）NarrationRequest/Response Schema

依赖：D-01、B-03。  
验收：未知字段、未知事件、缺失 claim 支持均严格拒绝。

### E-04（P0）Intent Parser

依赖：E-01、E-03。  
验收：低置信度的攻击、消费和不可逆行动要求澄清；元命令不进入 LLM。

### E-05（P0）Narrator 上下文组装

依赖：D-04、D-05、E-03。  
验收：请求中只包含角色可见状态和批准事实；私有资料云端开关生效。

### E-06（P0）输出校验与一次修复

依赖：D-06、E-05。  
验收：失败只重试一次；再次失败使用模板，不提交非法文本。

### E-07（P1）回顾与一生纪事生成

依赖：B-08、E-01。  
验收：只总结已提交事件，不新增人物、原因或结局。

### E-08（P1）费用与 token 预算

依赖：E-02。  
验收：超过单回合上限前阻止请求或缩短上下文，不事后静默超额。

## 8. Epic F：内容与场景

### F-01（P0）Scene/Transition 内容 Schema

依赖：D-01、B-04。  
验收：内容验证器检查入口、出口、fallback、LoreRequirement 和年龄标签。

### F-02（P0）固定教程生命片段

实现“8 岁配给日”到第一次灰籍异常的 20–30 分钟无 LLM 也可玩片段。  
依赖：F-01、B-03、C-03。  
验收：三种出身至少一种可端到端游玩；所有事实可用占位 `game_original`，不得伪装官方 Lore。

### F-03（P1）三种童年出身

依赖：F-02、D-10。  
验收：各有 5 个必经、8 个可选和 3 个生活事件；内容安全测试通过。

### F-04（P1）少年章节

依赖：F-03、B-05。  
验收：职业分配受童年状态影响；至少一次角色观点/百科对照。

### F-05（P1）四条青年职业路线

依赖：F-04、B-07。  
验收：每路线至少 5 个独有场景、3 份互补证据、2 种非战斗方案。

### F-06（P1）壮年汇合与灰籍抉择

依赖：F-05。  
验收：四路线均能从不同证据进入最终立场；不存在必须成功一次骰点的关键线索。

### F-07（P1）晚年与终局

依赖：F-06、B-08、E-07。  
验收：至少 6 类终局；童年关键关系至少在晚年有一次回响。

### F-08（P2）自然语言自定义童年

依赖：F-03、E-04、D-04。  
验收：越权、跨时代和未安装内容包的背景会被改写或拒绝。

## 9. Epic G：CLI 与 UX

### G-01（P0）程序级 CLI

依赖：A-01、C-03。  
验收：new/continue/saves/version/doctor 基础命令可用。

### G-02（P0）游戏循环与渲染

依赖：G-01、F-02、E-06。  
验收：编号选择和自然语言可混用；无颜色模式信息不丢失。

### G-03（P1）百科、知识和来源命令

依赖：D-05、D-09。  
验收：`/encyclopedia`、`/know`、`/sources`返回不同权限层数据。

### G-04（P1）检定详情与审计

依赖：B-03、A-04。  
验收：显示骰点、目标、全部修正及来源，不询问 LLM。

### G-05（P1）内容设置与年龄适配

依赖：F-01。  
验收：儿童情色标签永远拒绝；暴力淡出和跳过场景可用。

### G-06（P1）时间跳跃确认界面

依赖：B-04、G-02。  
验收：先预览后确认；取消不产生事件。

## 10. Epic H：质量与发布

### H-01（P0）CI 基线

依赖：A-01。  
验收：lint、typecheck、unit、contract 测试自动执行。

### H-02（P1）Canon 测试框架

依赖：D-04、D-06。  
验收：支持正确、陷阱、无资料、视角冲突和提示注入用例。

### H-03（P1）故障注入测试

依赖：C-05、E-06。  
验收：数据库中断、Provider 超时、非法 JSON、缺包和哈希变化均有测试。

### H-04（P1）跨平台打包

依赖：G-05、H-01。  
验收：目标三平台安装与启动文档通过人工验证。

### H-05（P1）隐私、版权与非官方声明

依赖：D-09、C-06。  
验收：发布包无受限原文；README 明确非官方项目、数据处理方式和用户责任。

### H-06（P1）发布候选验收

依赖：所有 P0/P1。  
验收：执行 `TEST_ACCEPTANCE_PLAN.md` 全部发布门槛并生成报告。

## 11. 推荐开发顺序

### Sprint 1：可运行骨架

`A-01 -> A-02/A-03 -> C-01/C-02 -> D-01 -> E-01 -> G-01`

### Sprint 2：确定性生命片段

`B-01 -> B-02 -> B-03 -> C-03/C-04 -> F-01 -> F-02 -> G-02`

### Sprint 3：资料与反幻觉

`D-02 -> D-03 -> D-04/D-05 -> E-03/E-04/E-05 -> D-06/E-06`

### Sprint 4：完整生命系统

`B-04 -> B-05/B-06 -> B-07/B-08 -> G-06 -> E-07`

### Sprint 5–6：内容生产

`D-07/D-08/D-09/D-10 -> F-03 -> F-04 -> F-05 -> F-06 -> F-07`

### Sprint 7：发布

`G-03/G-04/G-05 -> H-02/H-03/H-04/H-05 -> H-06`

Sprint 是依赖批次，不是工期承诺。实际估时需在资料拥有情况和人工内容审核资源确认后进行。

## 12. 首个 AI 开发代理的起始任务

建议只交付以下范围给第一个开发 AI：

```text
完成 A-01、A-02、A-03、C-01、C-02、D-01、E-01、G-01、H-01。
不要编写真实 40K Lore，不要联网抓取资料，不要接入生产 API key。
使用 Stub Provider 和 game_original 测试夹具。
完成后提交测试结果、目录树、数据迁移说明及尚未实现清单。
```

这能先验证工程基础，同时避免开发 AI 在资料审核系统尚未完成时提前生成未经核验的背景内容。
