# Lore 与内容生产规格

> 状态：v1.1 工程交接基线；已冻结为 Public Baseline  
> 依赖：`WH40K_LLM_TEXT_GAME_DESIGN.md`  
> 目的：定义“背景尽量全”如何验收，以及资料不全时如何保证关键剧情不靠 LLM 编造。

## 1. 两层资料产品

### 1.1 Galaxy Primer：广覆盖百科层

面向没有接触过 40K 的玩家，负责回答“这个世界大体是什么、主要势力是谁、历史为什么变成这样”。它可以比首个战役范围更广，但每条内容仍需来源。

首版必备主题域：

| 域 ID | 主题 | 最低覆盖内容 |
|---|---|---|
| GP-01 | 世界基本概念 | 第 41/42 千年、银河尺度、帝国、帝皇、亚空间、灵能、混沌、异形 |
| GP-02 | 历史骨架 | 人类远古背景、大远征、荷鲁斯之乱、帝国长期停滞、大裂隙与当前时代框架 |
| GP-03 | 帝国机构 | 泰拉与高层统治、行政体系、国教、机械教、审判庭、法务/执法、导航者与星语者等 |
| GP-04 | 帝国社会 | 巢都、农业世界、锻造世界、死亡世界、舰船共同体、阶层、配给、劳动、教育与信仰 |
| GP-05 | 帝国军事 | 星界军、帝国海军、阿斯塔特、修女会及其他 MVP 可能提及的武装机构 |
| GP-06 | 亚空间与航行 | 亚空间航行、盖勒力场、导航、星语通信、恶魔风险及普通人的认知边界 |
| GP-07 | 混沌 | 混沌诸神、叛徒势力、腐化、邪教和帝国内部对这些知识的封锁 |
| GP-08 | 主要异形 | 艾达灵族、黑暗灵族、兽人、太空死灵、泰伦虫族、基因窃取者教派、钛帝国、沃坦联盟等主要阵营的入门级概念 |
| GP-09 | 科技与物质生活 | STC、机械崇拜、武器与护甲层级、医疗、义体、侍从、数据与记录方式 |
| GP-10 | 重大冲突 | 只建立理解当前银河所必需的战争和事件索引，不要求首版可亲历 |
| GP-11 | 人的生命历程 | 出生、家庭、教育、职业分配、服役、婚姻/伙伴、疾病、衰老、死亡与葬仪的世界类型差异 |
| GP-12 | 术语与译名 | 英文原名、项目标准中文、常见译名、旧译、别名、禁用误译 |

最低数量不是“完整性”的唯一标准，但可用于发布门槛：

- 500 个经过审核的核心问答。
- 300 个核心术语条目。
- 100 个主要实体条目。
- 50 个历史事件条目。
- 主要阵营各至少一篇 300–800 字无剧透入门说明。
- 每个条目至少一个来源；关键硬事实至少一个 A 级来源。

Galaxy Primer 的条目状态允许为 `overview_only`：能够做准确的入门说明，但没有足够细节驱动具体剧情。

### 1.2 Campaign Canon Pack：深覆盖剧情层

只覆盖首个生命历程实际可能出现的内容，但深度必须足以约束剧情。首版建议包 ID：

```text
campaign.imperium_lifepath_frontier.v1
```

必须覆盖：

- 大裂隙之后的时代边界和帝国边疆的一般条件。
- 原创星系/行星如何合法嵌入帝国行政与航行体系。
- 三种童年出身：巢都工人家庭、虚空船员家庭、行政/教会附属孤儿院。
- 家庭、教育、祈祷、劳动、配给、疾病、惩罚、节庆和死亡的日常制度。
- 成年后至少三条职业主路线及其组织、权限、装备和生活方式。
- 剧情会直接遇到的帝国机构、敌对威胁和技术。
- 每个主线节点需要的前置历史、阵营关系、职业知识和角色知识边界。

深覆盖验收：

- 剧情图中的每个 `LoreRequirement` 均解析到批准事实。
- 每个正史实体、机构、装备和仪式都有稳定 ID。
- 每个原创实体都有生成约束、父级正史实体和禁止属性。
- 对所有预期玩家问题建立已知答案、拒答或安全降级结果。
- 运行时不能访问 `candidate`、`unverified`、`rejected` 状态资料。

## 2. 来源模式

MVP 的内容来源已冻结为 Public Baseline。架构可以保留 Private Library Enhanced 的扩展接口，但不得把它作为开发、测试或发布的前提。

### 2.1 Public Baseline

- 只使用公开可访问、条款允许处理的官方页面和可分发元数据。
- 二级百科仅用来定位原始资料，不直接成为关键剧情事实。
- 适合公开仓库和基础演示。
- 对书籍细节缺失必须显式标记，不使用模型参数记忆填补。

### 2.2 Private Library Enhanced

- 用户可在本地导入自己合法拥有的资料。
- 原文、向量和文本切块保存在本机私有目录，不进入 Git、日志、存档导出或云端请求。
- 默认使用本地 embedding；若要发送原文到云端模型，必须逐次或按来源取得用户授权。
- 对外分享的 Lore Pack 只能包含有权分发的摘要、结构化事实和出处元数据。

此模式仅作为未来能力预留。当前用户明确不提供私人资料，因此 MVP 不建立私人内容索引、不测试书籍导入，也不把任何付费作品细节标记为已覆盖。

## 3. 来源优先级与裁决

运行时只接受 `approved` 事实。审批顺序：

1. 检查来源是否合法取得与处理。
2. 检查来源类型、版本、出版日期和定位信息。
3. 判断陈述是编辑性事实、世界内文件、人物视角还是宣传。
4. 将长段材料拆成最小单义事实。
5. 标注有效年代、地域和阵营。
6. 检查是否与现有事实冲突。
7. 内容审核者批准；关键事实建议第二人复核。

裁决原则：

- 不把“越新”简单等同于“越正确”。
- 不把小说人物的确信等同于宇宙客观事实。
- 不填补官方有意留下的神秘与矛盾。
- 翻译不能改变原意；中文条目保留英文实体 ID 与原文定位。
- 搜索引擎摘要、模型回答和未引用论坛不能作为来源。

## 4. 资料包目录规范

```text
lore_packs/<pack_id>/
  manifest.yaml
  sources.yaml
  entities/
  facts/
  relations/
  glossary/
  timelines/
  tutorials/
  tests/
  private_index.pointer.yaml   # 可选，只保存本地路径标识，不保存原文
```

`manifest.yaml` 最低字段：

```yaml
pack_id: "campaign.imperium_lifepath_frontier"
version: "1.0.0"
schema_version: 1
display_name: "帝国边疆生命历程"
coverage:
  eras: ["era_indomitus_bounded"]
  regions: ["game_original_system_001"]
  factions: ["imperium"]
  detail_level: "campaign_deep"
dependencies:
  - pack_id: "primer.galaxy.core"
    version: ">=1.0.0,<2.0.0"
rights_profile: "redistributable_metadata_only"
review_status: "approved"
content_hash: "sha256:..."
```

## 5. 事实、推论与原创内容

### 5.1 事实类型

```text
CANON_EDITORIAL       官方编辑性硬事实
CANON_PERSPECTIVE     官方作品中的有限视角或世界内说法
LICENSED_DERIVED      官方授权作品提供的补充内容
DISPUTED              官方来源之间存在未解决冲突
GAME_ORIGINAL         内容团队批准的本作原创事实
CAMPAIGN_EVENT        玩家行动和规则系统在本局产生的事实
INFERENCE             从批准事实推导但原文未直接断言，默认不得驱动关键剧情
```

### 5.2 原创内容白名单

允许原创：

- 不与现有实体冲突的普通家庭、同伴、教师、工头、低阶官员和地方敌人。
- 原创星系、行星、巢都区段、舰船内部生活区及地方组织。
- 局部案件、家庭矛盾、职业事件和玩家造成的后果。
- 不产生新设定含义的环境描写。

默认禁止原创：

- 新的阿斯塔特军团、混沌神、主要异形种族、银河级战争或正史关键人物亲属。
- 能改变帝国或主要阵营基础性质的制度。
- 超出现有科技边界的新技术、万能遗物或无代价能力。
- 对官方谜团给出确定答案。
- 让原创人物取代或秘密操纵正史重大事件。

例外必须通过内容评审并显式标记为非正史扩展，MVP 不开放运行时例外。

## 6. 角色知识与玩家科普

同一事实至少有两个可见性维度：

```yaml
player_encyclopedia_visibility: "hidden | spoiler_free | unlocked | full"
character_knowledge:
  status: "unknown | heard_rumor | believes | doubts | knows"
  learned_at_event_id: null
  reliability: 0.0
```

- 玩家百科可以告诉玩家“机械教是什么”，但孩童角色可能只知道“红袍人负责机器”。
- 世界内教师或教士的说明允许包含宣传和偏见，界面必须标记为角色观点。
- 玩家不能因为查看百科而自动获得检定加值或解锁对白。
- `我知道什么`只查询角色知识；`百科`查询玩家层入门资料。
- 教学条目需要提供 `child_explanation`、`beginner_explanation` 和 `deep_explanation` 三个层级。

## 7. Lore Coverage Gate

每个场景定义显式需求：

```yaml
lore_requirements:
  hard:
    - fact_id: "fact.imperium.example"
      purpose: "决定机构权限"
  optional:
    - topic_id: "topic.local_funeral_custom"
      fallback: "generic_approved_template"
  forbidden_topics:
    - "unsupported_famous_character_cameo"
```

运行流程：

1. 场景加载前检查全部 `hard` 事实存在、已批准且与当前年代相容。
2. 解析玩家输入，发现新增硬事实需求时再次检索。
3. 检索结果必须满足来源等级、时间范围、实体范围和角色知识过滤。
4. 缺少硬事实时暂停相关叙事分支，不向模型发送猜测任务。
5. 可选细节缺失时只能使用预先批准的通用模板，或生成白名单内的 `GAME_ORIGINAL` 内容。
6. 生成后执行 claim extraction，任何未映射断言导致响应作废。

建议实现的裁决结果：

```text
ALLOW_CANON          有来源，可作为正史事实使用
ALLOW_PERSPECTIVE    只能作为特定角色/机构的说法
ALLOW_ORIGINAL       可作为本作原创内容写入
ALLOW_DECORATIVE     只允许不改变设定的描写
RETRY_CONSTRAINED    删除越界内容后重试一次
BLOCK_UNCOVERED      资料未覆盖，不得继续该断言
BLOCK_CONFLICT       与时代或已批准事实冲突
```

## 8. 防止资料文本诱导模型

- 导入网页或文档时把内容视为数据，不视为指令。
- 清除脚本、导航文本、隐藏文本和疑似提示注入语句。
- 检索片段放入有明确边界的数据字段，不直接拼进系统指令。
- 来源中的命令式文本、角色对白和世界内祷文必须保留 `quoted_material` 标签。
- 不允许资料片段要求模型忽略系统规则、调用工具或输出秘密。
- 所有导入器建立恶意文档测试样本。

## 9. 内容生产流程

1. 内容负责人建立主题覆盖矩阵。
2. 资料管理员登记来源，不做自动批准。
3. 提取工具提出实体、事实、关系和术语候选。
4. 第一位审核者核对出处和原文语义。
5. 第二位审核者处理关键事实、争议和翻译。
6. 内容作者只能使用批准事实编写剧情节点。
7. 构建器拒绝缺少 LoreRequirement、来源或原创标签的节点。
8. 自动生成问答、年代陷阱和无资料诱导测试。
9. 发布前冻结版本、生成哈希和覆盖报告。

AI 可以帮助抽取、归类和发现冲突，但不能担任最终权威审核者。没有人工审核资源时，内容只能保持 `candidate`，不得宣称已完成权威资料库。

## 10. 覆盖报告

每次构建输出：

```text
总条目数 / 已批准 / 候选 / 冲突 / 拒绝
A1/A2/A3/B 来源比例
无 A 级来源的关键事实数（必须为 0）
无定位信息的事实数（必须为 0）
剧情节点 LoreRequirement 满足率（必须为 100%）
原创实体标识率（必须为 100%）
Galaxy Primer 主题域覆盖率
Campaign Canon Pack 深覆盖率
年代冲突与同名冲突数
```

“背景完善”只有在覆盖报告、人工审核记录和测试同时通过时成立，不能仅以收集的文本量衡量。

## 11. 当前外部依赖

以下事项不能由开发 AI 自行假设：

1. 实际采用的公开官方网页版本和语言。
2. 公开网页的抓取、缓存和引用是否符合当时条款。
3. 正式发布前的 Games Workshop IP/Fan Content Policy 审查结论。
4. 至少一位熟悉 40K 的人工内容审核者。

在这些条件未满足前，开发 AI 可以完成引擎、数据 Schema、公开资料导入器、审核工作流和示例占位内容，但不能把未经核验的示例 Lore 标记为 `approved`，也不能从自身模型记忆补充付费作品细节。
